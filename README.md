# Product Agent

Product Agent 是一个面向持续科研调研的 Web 工作台。它不只回答一次问题，而是围绕同一研究主题持续完成：

`创建研究 -> 导入或检索论文 -> 生成结构化结果 -> 继续追问 -> 汇总研究总览 -> 沉淀工作记忆与知识`

当前产品价值主要体现在三点：

1. 将系统检索论文和用户上传 PDF 组织为可追溯的证据池。
2. 基于论文生成 taxonomy、研究关系图谱、研究空白和研究建议。
3. 在多轮追问中继承研究约束、历史结论和论文资产，而不是每轮从零开始。

## 当前进度

截至 2026-06-15，以下能力已经真实接入前后端主链：

- 会话、消息、研究任务、历史记录和 SQLite 持久化。
- 首轮研究与 follow-up task。
- task 级“本次结果”和 conversation 级“本研究总览”。
- 系统论文检索、核心分析池与扩展证据池。
- 创建研究前及研究过程中批量导入 PDF，单批最多 10 篇、单篇不超过 20 MB。
- 按标题、DOI、arXiv ID 或链接识别论文候选并导入当前研究或共享知识。
- `hybrid / imported_only / search_only` 研究方式。
- `none / conversation_only / shared` 知识范围。
- working memory、历史 workspace hints、近期对话和知识命中组成的研究上下文。
- Skill 新增、编辑、启停、删除、依赖工具校验和任务级选择。
- taxonomy、论文证据、研究关系图谱、研究空白和研究建议展示。
- 研究空白与建议的结论证据契约：绑定论文、证据等级和证据理由。

当前仍需重点优化的不是继续堆功能，而是：

- 检索召回率、主题相关性和追问补搜稳定性。
- conversation 总览对多轮结论的语义合并质量。
- 图谱强关系的全文证据覆盖率。
- RAG 命中来源的全文查看与更直观解释。
- 固定演示链路、bad case 回归集和优化前后评测数据。

详见 [任务清单](docs/任务清单.md)。

## 本地启动

### 1. 准备后端环境

在仓库根目录创建 `.env`：

```powershell
cd D:\product_agent
Copy-Item .env.example .env
```

按需要填写模型密钥，具体变量见 [本地环境变量说明](docs/本地环境变量说明.md)。

### 2. 启动后端

```powershell
cd D:\product_agent
python .\start_backend.py
```

默认地址：

- API：`http://127.0.0.1:8001`
- Swagger：`http://127.0.0.1:8001/docs`

若 `8001` 被占用，可运行：

```powershell
python .\start_backend.py --port 8002
```

前端默认请求 `8001`，并保留 `8000` 本地回退。

### 3. 启动前端

```powershell
cd D:\product_agent\ui
npm install
npm run dev
```

默认地址：`http://127.0.0.1:5173`

## 推荐手动主链

1. 新建研究，填写研究名称和研究主题。
2. 可选：先批量选择 PDF；PDF 只进入当前研究论文池，不会自动运行任务。
3. 选择研究方式、知识范围和 Skill。
4. 点击运行，查看“本次结果”中的论文证据、taxonomy、图谱、空白和建议。
5. 返回对话发送带约束的追问，例如限定年份、方法维度或评测场景。
6. 打开追问的“本次结果”，检查新增论文、沿用论文和检索说明。
7. 切换到“本研究总览”，检查多轮论文、结论和 working memory 是否完成融合。

## 仓库结构

- `api/`：FastAPI 路由与 handler。
- `services/`：产品业务编排、检索上下文、workspace 聚合与证据规则。
- `repositories/`：SQLite 与内存仓储。
- `schemas/`：前后端接口合同。
- `domain/`：领域实体。
- `research_agent/`：研究分析 pipeline。
- `ui/`：React + Vite 前端。
- `tests/`：后端单元测试和回归测试。
- `docs/`：架构、接口、任务、RAG 和字段说明。

## 开发边界

1. 前端只依赖 API 和 `schemas/` 合同，不自行推导论文关系或证据等级。
2. handler 不直接访问 repository，业务规则放在 `services/`。
3. 检索命中只能作为研究上下文；只有进入当前分析论文池的论文才能支撑 taxonomy、图谱和结论。
4. 研究空白与建议必须区分 `direct / indirect / exploratory`，无绑定论文时不能包装成已证实结论。
5. 不要为了页面“看起来丰富”重新引入 seed 论文污染、虚假引用或无依据强关系。

## 当前状态一句话总结

**主链和课程要求已经基本闭环，下一阶段应把精力集中在结果质量、证据可信度和稳定演示，而不是继续横向堆页面。**
