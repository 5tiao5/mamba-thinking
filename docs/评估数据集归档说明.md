# 评估数据集归档说明

更新时间：2026-06-18

本文用于说明优化过程中使用的评估数据集、历史评测输出和复现方式，满足“优化过程中的评估数据集需要存档保留”的交付要求。

## 1. 归档目录

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 检索质量评测集 | `evaluation/retrieval_cases.json` | 面向单次检索质量，检查查得到、查得准和约束遵守 |
| 主链验收用例 | `evaluation/main_chain_cases.json` | 面向完整产品链路，检查首轮、追问、工作台和总览 |
| 检索评测脚本 | `evaluation/retrieval_quality.py` | 读取检索评测集并输出 JSON/Markdown 报告 |
| 盲测脚本 | `evaluation/blind_retrieval_smoke.py` | 用于快速检查新主题下检索是否明显跑偏 |
| 历史评测输出 | `outputs/retrieval_eval/` | 保存历次检索质量评测的 JSON 和 Markdown 报告 |
| 质量说明文档 | `docs/检索质量评测说明.md` | 解释检索评测指标和运行方式 |
| 主链验收说明 | `docs/主链质量验收说明.md` | 解释端到端主链验收红线和用例 |

## 2. 检索质量评测集

文件：

```text
evaluation/retrieval_cases.json
```

用途：

- 验证用户提出合理科研主题后系统能否找到真实论文。
- 验证返回论文是否覆盖用户输入中的多个独立概念。
- 验证年份、主题和 forbidden terms 等约束是否被遵守。

评测集首版包含 10 个案例，覆盖：

- AI Agent 工具使用可靠性评测。
- function calling 鲁棒性。
- AI Agent for Software Engineering。
- Agent-Centric 软件开发方法论。
- 软件工程 Agent 的 episodic memory。
- 近两年与近三年的代码 Agent 论文。
- 多 Agent 软件工程 workflow。
- 科研助手 RAG 与证据引用。
- LLM Agent failure modes。

每个案例包含：

- `topic`：用户输入主题。
- `query_intent`：人工标注的研究意图。
- `expectations`：最低真实论文数、直接论文数、precision@k、概念覆盖和 forbidden terms。
- `rationale`：该案例为什么重要。

## 3. 主链验收用例

文件：

```text
evaluation/main_chain_cases.json
```

用途：

- 验证完整产品体验，而不是只看单点检索。
- 覆盖“新建研究 -> 首轮生成 -> 追问 -> 本次结果 -> 本研究总览”。
- 固化历史 bad case，避免修好后反复回归。

全局硬门禁包括：

- 不允许静默 fallback。
- 有约束追问必须触发补搜或给出无新增原因。
- 明显跑题论文不能进入核心分析池。
- 引用数未知不能显示为 `0`。
- taxonomy 分支论文数必须和详情展示一致。
- 强图谱关系必须有证据。
- 空白和建议必须有结论证据契约。
- 知识命中不能直接冒充论文证据。
- 研究总览不能盲目覆盖旧价值。

## 4. 历史评测输出

目录：

```text
outputs/retrieval_eval/
```

文件命名格式：

```text
retrieval-quality-YYYYMMDD-HHMMSS.json
retrieval-quality-YYYYMMDD-HHMMSS.md
```

说明：

- JSON 文件保留每个案例的详细结果，便于追溯。
- Markdown 文件保留概要表格，便于答辩或汇报。
- 早期报告中可能出现全部失败或低分，这是优化前/中过程的一部分，应保留而不是删除。它能说明问题发现和优化迭代是真实发生的。

## 5. 复现命令

### 5.1 只校验数据集格式

```powershell
cd D:\product_agent
python .\evaluation\retrieval_quality.py --validate-only
```

### 5.2 运行单个案例

```powershell
python .\evaluation\retrieval_quality.py --case agent_tool_use_evaluation
```

### 5.3 运行核心回归案例

```powershell
python .\evaluation\retrieval_quality.py `
  --case agent_tool_use_evaluation `
  --case software_engineering_agents `
  --case recent_two_years_code_agents
```

### 5.4 运行全部检索评测

```powershell
python .\evaluation\retrieval_quality.py
```

输出会写入：

```text
outputs/retrieval_eval/
```

## 6. 评测指标

| 指标 | 含义 |
| --- | --- |
| `real_paper_count` | 排除 seed/fallback 后的真实论文数 |
| `direct_paper_count` | 被系统判定为直接证据的论文数 |
| `adjacent_paper_count` | 部分相关、可补充背景的论文数 |
| `precision_at_k` | 前 K 个结果中满足人工主题契约的比例 |
| `constraint_pass_rate` | 年份、主题等硬约束满足比例 |
| `score` | 综合评分，覆盖查得到、查得准、直接证据和约束遵守 |

## 7. 优化过程中的数据使用方式

| 阶段 | 使用数据 | 目的 |
| --- | --- | --- |
| 问题发现 | 手动主链 bad case + `main_chain_cases.json` | 发现追问不补搜、跑题论文、引用显示错误等问题 |
| 检索优化 | `retrieval_cases.json` | 验证 query decomposition、多源召回和相关性筛选 |
| 证据优化 | 主链用例 + workspace 手测 | 验证 gaps/ideas 是否绑定论文和证据等级 |
| RAG 优化 | 共享知识污染用例 | 确保知识命中只作为上下文，不直接支撑结论 |
| UI 优化 | 固定主链手测 | 检查工作台展示、Agent 运行图、论文详情和追问建议 |

## 8. 归档规则

1. 评测数据集文件不得随意删除。
2. 修改评测集时，应说明新增或修改案例的原因。
3. 历史输出可以保留多份，不应只保留最好的一次结果。
4. 如果因为外部 API 限流导致失败，需要在报告或提交说明中标注。
5. 答辩前应至少保留一次完整主链手测记录和一次检索评测输出。
