# 调用关系参考

这份文档解决的不是“接口字段长什么样”，而是：

**当我要实现某个功能时，应该从哪个入口开始，调用哪个类、哪个函数，不该绕过哪些层。**

---

## 1. 总原则

推荐调用顺序：

`FastAPI route -> ProductApiHandlers -> Service -> Repository / Registry / research_agent`

也就是说：

- 前端只调 HTTP 接口
- `fastapi_app.py` 只负责路由
- `handlers.py` 只负责收参数、调 service、包响应
- 复杂业务逻辑放到 `services/`
- Agent 运行逻辑放到 `research_agent/`
- 数据存取放到 `repositories/`

当前要特别注意：
- 不要默认存在“会话详情 / 会话列表 / 任务列表”这些查询接口
- 如果要做 `HistoryPage`，先确认后端是否已经补了对应 route 和 handler

不要出现：

- handler 直接访问 repository
- 前端直接理解旧版 Agent state
- 页面逻辑绕开 API 直接耦到 Python 细节

---

## 2. 应用装配从哪里看

先看：

- `product_agent/app_container.py`

它负责：

- 创建 repository
- 创建 registry
- 创建 service
- 注册默认 tools / skills

如果组员问“这个 service 从哪来的”，先看它。

## 3. 常见功能的调用链

### 3.1 新建会话

`POST /conversations`

调用链：

- `fastapi_app.py -> create_conversation`
- `handlers.py -> ProductApiHandlers.create_conversation`
- `conversation_service.py -> ConversationService.create_conversation`
- `ConversationRepository.create`

### 3.2 读 / 写消息

`GET /conversations/{conversation_id}/messages`  
`POST /conversations/{conversation_id}/messages`

调用链：

- `handlers.py -> list_messages / create_message`
- `message_service.py -> list_messages / create_message`
- `MessageRepository.list_by_conversation / create`

### 3.3 继续对话并创建 follow-up task

`POST /conversations/continue`

调用链：

- `handlers.py -> ProductApiHandlers.continue_conversation`
- `conversation_service.py -> get_conversation`
- `message_service.py -> create_message`
- `message_service.py -> get_recent_context`
- `research_service.py -> create_follow_up_task`
- `ResearchTaskRepository.create`

这是当前最值得前后端都理解清楚的一条新链路。

### 3.4 创建研究任务

`POST /research/tasks`

调用链：

- `handlers.py -> create_research_task`
- `research_service.py -> create_task`
- `ResearchTaskRepository.create`

### 3.5 运行研究任务

`POST /research/tasks/{task_id}/run`

调用链：

- `handlers.py -> run_research_task`
- `research_service.py -> get_task`
- `research_service.py -> run_task`
- `research_agent/pipeline.py -> run_pipeline`
- `workspace_mapper.py -> workspace_from_agent_state`
- `WorkspaceRepository.save`

### 3.6 读取工作台

`GET /research/tasks/{task_id}/workspace`

调用链：

- `handlers.py -> get_workspace`
- `workspace_service.py -> get_workspace_snapshot`
- `WorkspaceRepository.get_by_task`

重点：

- handler 不再自己拼 workspace 字典
- 前端消费的是稳定的 snapshot 结果

### 3.7 工具管理

`GET /tools`  
`PATCH /tools/{tool_id}`

调用链：

- `handlers.py -> list_tools / update_tool`
- `tool_service.py -> list_tools / update_tool_enabled`
- `tool_registry.py`

### 3.8 Skill 管理

`GET /skills`

调用链：

- `handlers.py -> list_skills`
- `skill_service.py -> list_skills`
- `skill_registry.py`

### 3.9 当前不存在但容易被误以为存在的链路

这些需求现在还不能直接照着接口调：

- 打开单个会话详情：`GET /conversations/{conversation_id}` 尚未提供
- 拉取会话列表：`GET /conversations` 尚未提供
- 拉取任务列表：`GET /research/tasks` 尚未提供

所以如果组员在做历史页或列表页，不要先假设“后端应该已经有了”，而是先回到 `fastapi_app.py` 确认。

## 6. 一句话总结

如果组员忘了某个接口是干什么的，不要靠硬背。  
应该这样查：

- 看 `任务清单` 知道自己改哪里
- 看 `调用关系参考` 知道该调谁
- 看 `接口与函数参考文档` 知道参数和返回值

这样项目就不会变成“每个人都靠脑补理解架构”的黑箱。
