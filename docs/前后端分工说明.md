# 前后端分工说明

这份文档只做一件事：

**把前端现在要完成什么、后端现在要完成什么，讲清楚。**

前端 2 人和后端 2 人内部怎么再细分，可以各自再商量。

---

## 1. 当前项目的开发重点

现在 `product_agent/` 已经有：

- FastAPI 后端骨架
- React + Vite 前端骨架
- 会话链路
- 消息链路
- follow-up task 链路
- 研究任务主链路
- workspace 映射层

所以现在不是从零开始，而是：

**在既有骨架上，把“主链路”做成真的可操作产品。**

---

## 2. 前端目前要完成什么

前端现在的总目标：

**把“会话 -> 继续追问 -> 任务 -> 工作台结果”做成可操作的 Web 页面。**

### 2.1 首页 / 新建入口

要做：

- 输入 topic
- 创建会话
- 后续补创建任务
- 后续补创建成功后跳到对话页

主要文件：

- `product_agent/ui/src/pages/HomePage.tsx`

当前真实状态：

- 已经接通 `POST /conversations`
- 当前只会创建会话并显示 `conversation_id`
- 还没有自动创建任务
- 还没有自动跳转到对话页
- 所以上面“创建任务 / 跳转对话页”目前是目标项，不是已完成项

### 2.2 对话页

要做：

- 展示消息列表
- 输入消息并发送
- 调 `POST /conversations/continue`
- 展示 `context_preview`
- 展示 `follow_up_task`
- 给用户一个入口：是否立即运行 follow-up task

主要文件：

- `product_agent/ui/src/pages/ConversationPage.tsx`

这是前端当前最值得优先做实的一页。

### 2.3 工作台页

要做：

- 运行任务
- 展示 papers
- 展示 taxonomy
- 展示 graph
- 展示 gaps
- 展示 ideas
- 展示 trace
- 处理未运行 / 运行中 / 成功 / 失败状态

主要文件：

- `product_agent/ui/src/pages/WorkspacePage.tsx`

### 2.4 历史页

要做：

- 展示会话历史
- 展示最近任务
- 提供“继续会话”入口
- 提供“打开 workspace”入口

注意：

- 当前后端已经补出会话列表、会话详情、任务列表接口，可以开始真实联调

### 2.5 设置页

要做：

- 展示 tools / skills
- 工具启用/停用
- 工具配置编辑

---

## 3. 后端目前要完成什么

后端现在的总目标：

**把前端需要的接口、工作台数据和 Agent 分析能力稳定提供出来。**

### 3.1 会话与消息链路

要做：

- 创建会话
- 写消息
- 拉消息
- 为继续对话提供最近上下文
- 后续支持消息分页 / 历史查询

主要文件：

- `product_agent/api/handlers.py`
- `product_agent/services/conversation_service.py`
- `product_agent/services/message_service.py`

### 3.2 follow-up task 链路

要做：

- 让 `continue_conversation` 真正基于消息和 focus 创建 follow-up task
- 后续支持“创建后立即运行”
- 后续支持更真实的上下文摘要

主要文件：

- `product_agent/api/handlers.py`
- `product_agent/services/research_service.py`

### 3.3 工作台链路

要做：

- 把 Agent 结果映射成前端稳定消费的数据
- 继续收紧 `taxonomy / graph / trace`

主要文件：

- `product_agent/services/workspace_service.py`
- `product_agent/services/workspace_mapper.py`

### 3.4 Agent 分析能力

要做：

- 保证 `run_pipeline` 主链路稳定
- 继续把 `auditor / synthesizer` 细拆
- 继续优化 taxonomy / graph / gap / ideas 输出

主要文件：

- `product_agent/research_agent/`
- `product_agent/research_agent/nodes/auditor.py`
- `product_agent/research_agent/nodes/synthesizer.py`

### 3.5 tools / skills / knowledge

要做：

- 基于 SQLite 的工具配置持久化接入
- skill 依赖校验
- shared knowledge / RAG 的最小版接入

补充说明：
- 当前默认开发环境已经切到 SQLite
- 也就是说，历史会话、消息、任务、workspace 现在默认是可落盘的

---

## 4. 现在最适合组员做的工作

### 前端最适合现在做的

- 对话页消息流
- follow-up task 交互
- 工作台结果展示
- 设置页 tools / skills 展示

为什么适合：

- 接口已经存在
- 返回字段已经比较稳定
- 能真实联调，不是纯占位页面

### 后端最适合现在做的

- `continue_conversation` 上下文增强
- workspace 结构继续收紧
- 历史查询接口
- tool / skill / knowledge 的业务扩展
- `auditor / synthesizer` 继续细拆

为什么适合：

- 主链路已经有了
- 现在是“把骨架变实”的阶段

---

## 5. 组长重点盯什么

你现在最该盯的是：

- 前后端字段不能漂移
- 接口不能乱改
- handler 不能跨层乱调
- 新功能优先收敛到 `product_agent/`
- 组员先做能联调的真链路，不要先散开写边角功能

---

## 6. 一句话总结

现在最好的推进方式不是“每个人随便挑几个文件”，而是：

- 前端围绕对话页和工作台把产品页面做起来
- 后端围绕 follow-up task、workspace 和 Agent 主链路把核心能力做实

这两条线一旦都打通，项目就会明显从“脚手架”变成“真的能操作的产品”。
