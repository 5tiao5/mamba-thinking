# 前后端分工说明

这份文档的目标很直接：

**告诉组员现在前端应该做什么，后端应该做什么，哪些工作已经有地基，哪些是下一阶段的重点。**

默认分工方式：

- 前端 2 人
- 后端 2 人
- 组长负责接口冻结、进度统筹、代码集成与后端兜底

---

## 1. 当前项目处于什么阶段

`product_agent/` 已经完成了：

- FastAPI 后端骨架与核心主链路
- React + Vite 前端骨架与主要页面
- SQLite 默认持久化
- Conversation / Message / ResearchTask / Workspace 基本闭环

所以现在不是“先搭框架”，而是：

**在现有框架上继续把页面、交互、知识增强和搜索质量做实。**

## 4. 现在最适合的前后端协作方式

### 前端组

建议围绕这 3 条线分内部任务：

1. 对话流
2. 工作台流
3. 历史与设置流

### 后端组

建议围绕这 3 条线分内部任务：

1. 会话 / 消息 / 任务接口
2. 搜索 / taxonomy / workspace 质量
3. knowledge / RAG / 持久化扩展

---

## 5. 组长重点盯什么

你现在最该盯的是：

1. API 字段不能乱改
2. handler 不要越层访问 repository
3. 前端不要自己猜后端结构
4. 下一阶段重点放在质量增强与产品体验，而不是继续大改骨架

---

## 6. 一句话总结

现在最合理的推进方式不是“每个人随便挑两个文件”，而是：

- 前端组围绕对话、工作台、历史体验继续做实
- 后端组围绕搜索、taxonomy、knowledge 继续补核心能力

这样下一阶段的开发会更稳，也更像真正的产品推进。
