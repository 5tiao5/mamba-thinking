# 前后端分工说明

更新时间：2026-06-15

当前项目已经越过“搭骨架”阶段。分工原则应从功能堆叠切换为：

**前端负责把证据与研究演化讲清楚，后端负责保证检索、合并和证据判定可靠。**

## 1. 已冻结的共同认知

- 一个 `Conversation` 表示长期研究主题。
- 一个 `ResearchTask` 表示首轮生成或某次追问。
- “本次结果”读取 task workspace。
- “本研究总览”聚合同一 conversation 下的完成任务。
- 论文分为扩展证据池和核心分析池。
- 用户上传 PDF、系统检索论文和共享知识必须保留来源身份。
- 知识命中用于辅助上下文，不等于论文已经证明结论。
- graph、taxonomy、gaps 和 ideas 由后端生成，前端只负责解释和交互。

## 2. 前端职责

### 已完成

- 新建研究和历史研究导航。
- 对话、追问、任务运行和工作台跳转。
- 研究方式、知识范围和 Skill 选择。
- 创建研究前批量选择 PDF。
- 研究过程中批量导入 PDF 和查看论文池。
- 论文候选识别和导入。
- Tool 启停。
- Skill 新增、编辑、启停、删除和依赖工具多选。
- “本次结果”与“本研究总览”切换。
- 论文证据、taxonomy、图谱、研究空白、建议和 working memory 展示。
- RAG 命中、supporting snippets 和结论证据展开。

### 下一阶段

1. 增加知识文档详情或全文查看入口。
2. 将研究总览更明确地表达为“多轮研究演化”，而不是结果堆叠。
3. 统一检索失败、证据不足、探索性建议和 fallback 的状态语言。
4. 优化大量论文和多轮数据下的信息密度。
5. 维护固定主链的桌面端视觉回归。

### 前端禁止事项

- 不根据标题相似度自行生成 graph edge。
- 不把引用数未知渲染为确定的 `0`。
- 不把 knowledge hit 标成论文证据。
- 不在前端重新计算核心论文池或结论证据等级。
- 不绕过 API 直接依赖数据库结构。

## 3. 后端职责

### 已完成

- 会话、消息、任务、workspace 和 SQLite 主链。
- follow-up task 与 assistant 结果回写。
- 多种研究方式和知识范围。
- 系统检索、用户论文池、核心分析池与来源标记。
- query decomposition 和追问约束提取。
- working memory、inherited context 和 source trace。
- task workspace 与 conversation workspace 聚合。
- Skill CRUD、依赖校验、任务选择、上下文注入和 trace 记录。
- PDF 批量解析并写入当前研究论文池和知识文档。
- taxonomy grounding、关系证据过滤和结论准入契约。

### 下一阶段

1. 提升检索召回率、相关性筛选和追问补搜稳定性。
2. 给 query decomposition 增加覆盖检查，保证年份、方法、对象和场景约束不丢失。
3. 提高 conversation 总览对论文和结论的语义合并质量。
4. 扩大 graph 强关系的全文证据覆盖率。
5. 提供知识文档详情或全文读取接口。
6. 建立固定主题的检索与结论回归评测。

### 后端禁止事项

- 不用 seed 论文掩盖检索失败。
- 不允许共享知识中的论文 ID 越过当前分析池直接支撑结论。
- 不因页面需要“更丰富”而放宽强关系准入。
- 不让 handler 直接访问 repository。
- 不在多个节点复制上下文组装逻辑。

## 4. 当前稳定接口合同

前端应重点依赖：

- `/conversations`
- `/conversations/{conversation_id}/messages`
- `/conversations/continue`
- `/conversations/{conversation_id}/papers`
- `/conversations/{conversation_id}/papers/import-pdfs`
- `/conversations/{conversation_id}/workspace`
- `/research/tasks`
- `/research/tasks/{task_id}/run`
- `/research/tasks/{task_id}/workspace`
- `/knowledge/documents`
- `/knowledge/paper-candidates`
- `/knowledge/paper-candidates/import`
- `/skills`
- `/tools`

字段变更时必须同步：

- `schemas/`
- `ui/src/types/api.ts`
- `ui/src/lib/demoData.ts`
- 对应文档与测试

## 5. 推荐并行任务

### 前端 A：研究总览

- 多轮研究演化表达。
- working memory 和继承线索交互。
- 核心论文选择原因与来源展示。

### 前端 B：知识与证据

- 知识文档详情。
- RAG 命中来源解释。
- gaps / ideas 证据展开和状态统一。

### 后端 A：检索质量

- query decomposition 覆盖检查。
- 多源召回与排序。
- 年份和主题约束回归。

### 后端 B：证据与聚合

- conversation workspace 语义合并。
- 论文元数据继承。
- graph 全文证据和结论准入测试。

## 6. 联调验收

每轮功能不能只验证接口成功，应至少跑：

1. 新建研究。
2. 可选导入 PDF。
3. 运行首轮。
4. 发送会触发补搜的追问。
5. 检查本次结果中的新增论文。
6. 检查本研究总览中的多轮合并。
7. 展开 graph、RAG 命中和结论证据。
8. 检查浏览器控制台与后端日志。

## 7. 一句话总结

**前端要让用户看懂“系统为什么得出这个结论”，后端要保证这套解释经得起论文和数据核查。**
