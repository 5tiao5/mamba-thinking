# 后端接口规格说明

本文档描述当前 Product Agent 后端 FastAPI 接口的功能、请求规格、响应规格、错误码和前端调用方式。

适用版本：

- API title: `Product Agent API`
- API version: `0.1.0`
- 默认 Base URL: `http://127.0.0.1:8000`
- 当前本地兜底 Base URL: `http://127.0.0.1:8001`
- Swagger: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

启动方式：

```powershell
python start_backend.py
```

如 8000 端口被占用：

```powershell
python start_backend.py --no-reload --port 8001
```

---

## 1. 后端功能范围

当前后端围绕“科研调研智能体”主链路提供以下能力：

1. 会话管理：创建研究会话、列出历史会话、读取会话详情、删除会话。
2. 消息链路：读取会话消息、追加用户消息、继续追问并生成 follow-up task。
3. 研究任务：创建研究任务、列出任务、查看任务状态、运行任务。
4. 工作台结果：读取单个任务 workspace，或读取会话级聚合 workspace。
5. 工具与能力配置：列出工具、启停工具、列出 skills。
6. 知识库：导入知识文档、列出文档、删除文档、按关键词或标签检索知识。

主业务链路：

```text
POST /conversations
  -> POST /research/tasks
  -> POST /research/tasks/{task_id}/run
  -> GET /research/tasks/{task_id}/workspace
  -> POST /conversations/continue
  -> POST /research/tasks/{follow_up_task_id}/run
```

## 2. 统一响应格式

除 `GET /health` 外，业务接口统一返回 `ApiResponse<T>`。

成功响应：

```json
{
  "success": true,
  "data": {},
  "error": null,
  "trace_id": null
}
```

业务失败响应：

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "conversation_not_found",
    "message": "Conversation does not exist."
  },
  "trace_id": null
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `success` | `boolean` | 业务是否成功 |
| `data` | `object / array / null` | 成功时的数据主体 |
| `error` | `object / null` | 失败时的错误对象 |
| `error.code` | `string` | 稳定错误码，前端应优先判断该字段 |
| `error.message` | `string` | 面向开发和调试的错误说明 |
| `trace_id` | `string / null` | 预留链路追踪 ID |

注意：

- 业务失败通常仍是 HTTP 200，但 `success=false`。
- FastAPI 参数校验失败会返回 HTTP 422。
- 方法不存在会返回 HTTP 405。

## 5. 会话接口

### `POST /conversations`

功能：

- 创建一个新的研究会话。
- 一个会话代表用户围绕某个主题进行的一段长期研究。

请求体：

```json
{
  "topic": "AI Agent Tool Use 评测",
  "title": "工具调用评测研究"
}
```

请求字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `topic` | `string` | 是 | 本次会话的研究主题 |
| `title` | `string / null` | 否 | 会话标题；为空时回退为 `topic` |

成功响应：

```json
{
  "success": true,
  "data": {
    "conversation_id": "conv_xxxxxxxxxxxx",
    "topic": "AI Agent Tool Use 评测",
    "title": "工具调用评测研究"
  },
  "error": null,
  "trace_id": null
}
```

---

### `GET /conversations`

功能：

- 获取历史研究会话列表。
- 默认按最近更新时间倒序排列。

查询参数：

| 参数 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `limit` | `integer` | 否 | `1 <= limit <= 100` | 最多返回多少条 |

示例：

```text
GET /conversations?limit=20
```

成功响应：

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "conversation_id": "conv_xxx",
        "topic": "AI Agent Tool Use 评测",
        "title": "工具调用评测研究",
        "status": "active",
        "latest_task_id": "task_xxx",
        "created_at": "2026-05-25T08:30:00+00:00",
        "updated_at": "2026-05-25T08:45:00+00:00"
      }
    ]
  },
  "error": null,
  "trace_id": null
}
```

### `DELETE /conversations/{conversation_id}`

功能：

- 删除指定会话。
- 会级联删除该会话下的消息、研究任务和任务 workspace 快照。
- 用于前端左侧历史记录删除。

路径参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `conversation_id` | `string` | 会话 ID |

成功响应：

```json
{
  "success": true,
  "data": {
    "conversation_id": "conv_xxx",
    "deleted": true,
    "deleted_messages": 3,
    "deleted_tasks": 2,
    "deleted_workspaces": 2
  },
  "error": null,
  "trace_id": null
}
```

错误：

| 错误码 | 说明 |
| --- | --- |
| `conversation_not_found` | 会话不存在 |

实现说明：

- 当前存储层没有完全依赖数据库外键 cascade。
- 服务层按顺序清理：workspace -> research task -> message -> conversation。

---

### `GET /conversations/{conversation_id}/workspace`

功能：

- 获取一个会话下所有已完成任务的聚合 workspace。
- 适合“一个研究会话最终结果”展示。

成功响应：

- 响应结构与 `GET /research/tasks/{task_id}/workspace` 相同。
- `task_id` 可能是形如 `conversation::{conversation_id}` 的聚合 ID。

错误：

| 错误码 | 说明 |
| --- | --- |
| `conversation_workspace_not_found` | 会话不存在或没有可聚合的 workspace |

### `POST /conversations/continue`

功能：

- 在已有会话上继续追问。
- 写入用户消息。
- 返回最近上下文预览。
- 检索相关知识库片段。
- 可选创建 follow-up 研究任务。

请求体：

```json
{
  "conversation_id": "conv_xxx",
  "content": "请只保留近两年的评测论文，并重新总结三个可做方向。",
  "focus": "recent benchmark papers",
  "create_follow_up_task": true,
  "mode": "balanced"
}
```

请求字段：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `conversation_id` | `string` | 是 | 无 | 会话 ID |
| `content` | `string` | 是 | 无 | 本轮追问内容 |
| `focus` | `string / null` | 否 | `null` | 本轮希望聚焦的子问题 |
| `create_follow_up_task` | `boolean` | 否 | `true` | 是否创建后续研究任务 |
| `mode` | `string` | 否 | `default` | 任务模式：`default / fast / balanced` |

成功响应：

```json
{
  "success": true,
  "data": {
    "conversation_id": "conv_xxx",
    "next_focus": "recent benchmark papers",
    "message": "请只保留近两年的评测论文，并重新总结三个可做方向。",
    "message_id": "msg_xxx",
    "context_preview": [
      "user: 我想调研 AI Agent Tool Use...",
      "assistant: 已完成本轮研究任务..."
    ],
    "knowledge_context": [
      "[Knowledge] 工具调用评测需要同时关注成功率、恢复能力、成本和延迟。"
    ],
    "follow_up_task": {
      "task_id": "task_xxx",
      "topic": "AI Agent Tool Use - recent benchmark papers",
      "status": "created",
      "trigger_message_id": "msg_xxx"
    }
  },
  "error": null,
  "trace_id": null
}
```

错误：

| 错误码 | 说明 |
| --- | --- |
| `conversation_not_found` | 会话不存在 |
| `task_invalid_mode` | 任务模式不合法 |

前端建议：

- 如果返回 `follow_up_task`，展示“运行并刷新结果”按钮。
- 用户点击后调用 `POST /research/tasks/{task_id}/run`。

## 7. 研究任务接口

### `POST /research/tasks`

功能：

- 创建一个研究任务，但不立即运行。
- 任务必须归属于一个已有会话。

请求体：

```json
{
  "conversation_id": "conv_xxx",
  "topic": "AI Agent Tool Use 评测",
  "mode": "balanced",
  "use_shared_knowledge": true,
  "enabled_tools": ["arxiv_search", "semantic_scholar"]
}
```

请求字段：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `conversation_id` | `string` | 是 | 无 | 归属会话 ID |
| `topic` | `string` | 是 | 无 | 任务研究主题 |
| `mode` | `string` | 否 | `default` | `default / fast / balanced` |
| `use_shared_knowledge` | `boolean` | 否 | `false` | 是否使用共享知识；当前字段已保留 |
| `enabled_tools` | `string[]` | 否 | `[]` | 指定工具列表；当前字段已保留 |

成功响应：

```json
{
  "success": true,
  "data": {
    "task_id": "task_xxx",
    "conversation_id": "conv_xxx",
    "status": "created"
  },
  "error": null,
  "trace_id": null
}
```

错误：

| 错误码 | 说明 |
| --- | --- |
| `conversation_not_found` | 会话不存在 |
| `task_invalid_mode` | 任务模式不合法 |

---

### `POST /research/tasks/{task_id}/run`

功能：

- 运行指定研究任务。
- 成功后保存 workspace。
- 成功或失败都会向会话写入 assistant 消息。
- 成功后会尽量自动把 workspace 摘要沉淀到知识库。

请求体：

- 无。

成功响应：

```json
{
  "success": true,
  "data": {
    "task_id": "task_xxx",
    "topic": "AI Agent Tool Use 评测",
    "alignment_score": 0.82,
    "trace_keys": ["thought_trace", "action_history", "context_inputs"],
    "assistant_message_id": "msg_xxx"
  },
  "error": null,
  "trace_id": null
}
```

任务状态变化：

```text
created -> running -> completed
created -> running -> failed
```

错误：

| 错误码 | 说明 |
| --- | --- |
| `task_not_found` | 任务不存在 |
| `task_run_failed` | 任务运行失败 |

---

### `GET /research/tasks/{task_id}/workspace`

功能：

- 获取某个任务产出的结构化研究结果。
- 前端主结果窗口主要依赖该接口。

成功响应：

```json
{
  "success": true,
  "data": {
    "task_id": "task_xxx",
    "topic": "AI Agent Tool Use 评测",
    "summary": "本轮研究聚焦工具调用评测...",
    "papers": [],
    "taxonomy": {},
    "graph_edges": [],
    "gaps": [],
    "ideas": [],
    "alignment_score": 0.82,
    "evidence_status": {
      "insufficient": false,
      "total_papers": 4,
      "real_paper_count": 4,
      "fallback_paper_count": 0,
      "fallback_ratio": 0,
      "covered_branch_count": 3,
      "candidate_branches": [],
      "message": "当前证据量足够支撑一版可解释的 taxonomy 草图。"
    },
    "trace": {
      "thought_trace": [],
      "action_history": [],
      "context_inputs": []
    }
  },
  "error": null,
  "trace_id": null
}
```

核心字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `task_id` | `string` | workspace 对应任务 ID |
| `topic` | `string` | 研究主题 |
| `summary` | `string` | 面向用户的简略总结 |
| `papers` | `WorkspacePaper[]` | 论文证据列表 |
| `taxonomy` | `object` | 分类树和覆盖度信息 |
| `graph_edges` | `WorkspaceGraphEdge[]` | 论文或概念关系边 |
| `gaps` | `WorkspaceGap[]` | 研究空白 |
| `ideas` | `WorkspaceIdea[]` | 可做研究方向 |
| `alignment_score` | `number` | 结果与主题的对齐分数 |
| `evidence_status` | `object` | 证据充足性说明 |
| `trace` | `object / null` | 过程记录和调试信息 |

错误：

| 错误码 | 说明 |
| --- | --- |
| `workspace_not_found` | workspace 不存在，通常说明任务还没运行成功 |

```json
{
  "success": true,

      "enabled": true,
      "config": {}
    }
  ],
  "error": null,
  "trace_id": null
}
```

---

### `PATCH /tools/{tool_id}`

功能：

- 更新某个工具的启用状态和配置。

请求体：

```json
{
  "enabled": true,
  "config": {
    "max_results": 8
  }
}
```

请求字段：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `enabled` | `boolean` | 是 | 无 | 是否启用工具 |
| `config` | `object` | 否 | `{}` | 工具配置 |

成功响应：

```json
{
  "success": true,
  "data": {
    "tool_id": "arxiv_search",
    "display_name": "ArXiv Search",
    "description": "Searches academic papers from ArXiv.",
    "enabled": true,
    "config": {
      "max_results": 8
    }
```

## 13. 当前接口边界和注意事项

1. `enabled_tools` 和 `use_shared_knowledge` 已在请求 schema 中保留，但研究运行逻辑对它们的使用仍可继续增强。
2. `taxonomy` 和 `trace` 内部结构相对灵活，前端应优先依赖顶层稳定字段。
3. `POST /research/tasks/{task_id}/run` 是同步接口，研究任务耗时较长时前端需要展示 loading。
4. 删除会话会真实删除关联消息、任务和 workspace，前端应二次确认。
5. `GET /conversations/{conversation_id}/workspace` 返回聚合结果，适合会话总览；单次任务详情仍应使用 `GET /research/tasks/{task_id}/workspace`。
