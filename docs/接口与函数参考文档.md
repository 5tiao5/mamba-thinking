## 2. FastAPI 接口总览

后端入口文件：

- [fastapi_app.py](/D:/iteration_two-master/iteration_two-master/product_agent/api/fastapi_app.py)

本地开发默认地址：

- API Base URL: `http://127.0.0.1:8000`
- Swagger 文档: `http://127.0.0.1:8000/docs`
- ReDoc 文档: `http://127.0.0.1:8000/redoc`

启动命令：

```powershell
uvicorn product_agent.api.fastapi_app:app --reload
```

### 2.1 `GET /health`

作用：

- 用于检查后端服务是否正常启动

返回：

```json
{
  "status": "ok"
}
```

### 2.2 `POST /conversations`

作用：

- 创建一个新的研究会话

请求体：

```json
{
  "topic": "AI Agent Tool Use",
  "title": "Agent 调研"
}
```

返回值：

```json
{
  "success": true,
  "data": {
    "conversation_id": "conv_xxx",
    "topic": "AI Agent Tool Use",
    "title": "Agent 调研"
  }
}
```

### 2.3 `POST /conversations/continue`

作用：

- 在已有会话上继续追问

请求体：

```json
{
  "conversation_id": "conv_xxx",
  "content": "只看 evaluation 相关论文",
  "focus": "evaluation"
}
```

返回值：

- 当前版本只冻结了接口契约
- 后续会真正驱动多轮上下文任务

### 2.4 `POST /research/tasks`

作用：

- 创建一次研究分析任务

请求体：

```json
{
  "conversation_id": "conv_xxx",
  "topic": "AI Agent Tool Use",
  "mode": "default",
  "use_shared_knowledge": false,
  "enabled_tools": []
}
```

返回值：

```json
{
  "success": true,
  "data": {
    "task_id": "task_xxx",
    "conversation_id": "conv_xxx",
    "status": "created"
  }
}
```

### 2.5 `POST /research/tasks/{task_id}/run`

作用：

- 真正运行该任务对应的 Agent 分析流程

返回值：

```json
{
  "success": true,
  "data": {
    "task_id": "task_xxx",
    "topic": "AI Agent Tool Use",
    "alignment_score": 0.72,
    "trace_keys": ["thought_trace", "action_history"]
  }
}
```

### 2.6 `GET /research/tasks/{task_id}/workspace`

作用：

- 获取任务执行后的工作台快照

返回值：

- 当前返回 summary、taxonomy、graph_edges、alignment_score
- 后续还要补 papers、gaps、ideas 的完整结构

### 2.7 `GET /tools`

作用：

- 获取当前已注册工具列表

### 2.8 `PATCH /tools/{tool_id}`

作用：

- 更新某个工具是否启用，以及它的配置

### 2.9 `GET /skills`

作用：

- 获取当前已注册 skill 列表

## 3. 核心服务函数总览

### 3.1 `ConversationService`

文件：

- [conversation_service.py](/D:/iteration_two-master/iteration_two-master/product_agent/services/conversation_service.py)

#### `create_conversation(topic, title=None) -> Conversation`

作用：

- 创建会话对象并写入仓储

作用：

调用者：

- `ProductApiHandlers.continue_conversation`

### 3.2 `ResearchService`

文件：

- [research_service.py](/D:/iteration_two-master/iteration_two-master/product_agent/services/research_service.py)

#### `create_task(conversation_id, topic, mode='default') -> ResearchTask`

作用：

- 创建任务记录，不真正执行 Agent

调用者：

- `ProductApiHandlers.create_research_task`

作用：

- 调用重构版 Agent pipeline
- 把运行结果投影为产品级工作台快照

调用者：

- `ProductApiHandlers.run_research_task`

- 当前这一步已经可跑

## 6. 开发建议

### 前端同学

优先围绕这些接口开发：

- `POST /conversations`
- `POST /research/tasks`
- `POST /research/tasks/{task_id}/run`
- `GET /research/tasks/{task_id}/workspace`
- `GET /tools`
- `GET /skills`

### 后端同学

优先补这些实现：

- `ResearchWorkspace` 的完整投影
- `continue_conversation` 的真正多轮逻辑
- registry 与 service 的扩展能力
- repository 的数据库版本

## 7. 结论

当前版本已经进入“接口冻结、按合同实现”的阶段。

团队后续开发应遵循两个原则：

1. 前端尽量只依赖 `schemas` 和 FastAPI 接口，不直接依赖内部状态结构
2. 后端尽量沿着 `service -> repository / registry -> agent core` 的方向扩展，而不是随意跨层调用
