# 接口与函数参考文档

## 1. 文档目的

这份文档回答四个问题：

- 这个接口是干什么的
- 请求参数长什么样
- 返回值长什么样
- 后端实际由哪个 service 负责

建议阅读顺序：

1. 前端同学优先看第 2 节
2. 后端同学优先看第 3 节
3. 所有人至少浏览第 4 节“当前哪些功能真的可用”

## 2. FastAPI 接口总览

后端入口文件：

- `product_agent/api/fastapi_app.py`

本地默认地址：

- API Base URL: `http://127.0.0.1:8000`
- Swagger: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

启动命令：

```powershell
uvicorn product_agent.api.fastapi_app:app --reload
```

### 2.1 `GET /health`

作用：

- 检查后端服务是否正常启动

### 2.2 `POST /conversations`

作用：

- 创建一个新会话

请求体：

```json
{
  "topic": "AI Agent Tool Use",
  "title": "Agent Research"
}
```

对应 service：

- `ConversationService.create_conversation`

### 2.3 `GET /conversations/{conversation_id}/messages`

作用：

- 获取某个会话的消息列表

对应 service：

- `MessageService.list_messages`

### 2.4 `POST /conversations/{conversation_id}/messages`

作用：

- 在指定会话中写入一条消息

对应 service：

- `MessageService.create_message`

### 2.5 `POST /conversations/continue`

作用：

- 在已有会话上继续追问

请求体：

```json
{
  "conversation_id": "conv_xxx",
  "content": "Only focus on benchmark and evaluation papers",
  "focus": "benchmark evaluation",
  "create_follow_up_task": true,
  "mode": "balanced"
}
```

当前返回重点：

- `message_id`
- `context_preview`
- `follow_up_task`

当前版本已经支持：

- 继续对话时写消息
- 读取最近上下文预览
- 创建一条 follow-up task 记录

对应 service：

- `ConversationService.get_conversation`
- `MessageService.create_message`
- `MessageService.get_recent_context`
- `ResearchService.create_follow_up_task`

### 2.6 `POST /research/tasks`

作用：

- 创建一轮研究分析任务

请求体：

```json
{
  "conversation_id": "conv_xxx",
  "topic": "AI Agent Tool Use",
  "mode": "default",
  "use_shared_knowledge": false,
  "enabled_tools": []
}
```

当前约束：

- `conversation_id` 必须存在
- `mode` 只能是 `default / fast / balanced`

对应 service：

- `ResearchService.create_task`

### 2.7 `POST /research/tasks/{task_id}/run`

作用：

- 真正运行该任务对应的 Agent 分析流程

当前行为：

- 任务开始前状态切到 `running`
- 成功后切到 `completed`
- 失败后切到 `failed`

对应 service：

- `ResearchService.get_task`
- `ResearchService.run_task`

### 2.8 `GET /research/tasks/{task_id}/workspace`

作用：

- 获取任务执行后的工作台快照

返回主体：

- `task_id`
- `topic`
- `summary`
- `papers`
- `taxonomy`
- `graph_edges`
- `gaps`
- `ideas`
- `alignment_score`
- `trace`

对应 service：

- `WorkspaceService.get_workspace_snapshot`

### 2.9 `GET /tools`

作用：

- 获取当前已注册工具列表

对应 service：

- `ToolService.list_tools`

### 2.10 `PATCH /tools/{tool_id}`

作用：

- 更新某个工具是否启用及其配置

对应 service：

- `ToolService.update_tool_enabled`

### 2.11 `GET /skills`

作用：

- 获取当前已注册 skill 列表

对应 service：

- `SkillService.list_skills`

## 3. 核心服务函数总览

### 3.1 `ConversationService`

文件：

- `product_agent/services/conversation_service.py`

关键函数：

- `create_conversation(topic, title=None) -> Conversation`
- `get_conversation(conversation_id) -> Conversation | None`

### 3.2 `MessageService`

文件：

- `product_agent/services/message_service.py`

关键函数：

- `create_message(...) -> MessageRecord | None`
- `list_messages(conversation_id) -> list[MessageRecord] | None`
- `get_recent_context(conversation_id, limit=6) -> list[MessageRecord] | None`

### 3.3 `ResearchService`

文件：

- `product_agent/services/research_service.py`

关键函数：

- `create_task(...) -> ResearchTask`
- `create_follow_up_task(...) -> ResearchTask`
- `get_task(task_id) -> ResearchTask`
- `run_task(task) -> ResearchWorkspace`

说明：

- `create_task` 做 conversation / mode 校验
- `create_follow_up_task` 把一轮追问转成任务记录
- `run_task` 负责任务状态流转和 workspace 持久化

### 3.4 `WorkspaceService`

文件：

- `product_agent/services/workspace_service.py`

关键函数：

- `get_workspace(task_id)`
- `get_workspace_snapshot(task_id) -> WorkspaceSnapshotResponse | None`

### 3.5 `KnowledgeService`

文件：

- `product_agent/services/knowledge_service.py`

作用：

- 承接 shared knowledge 与后续 RAG 的统一入口

## 4. 当前哪些功能真的可用

已经真实可用：

- 创建会话
- 写消息 / 拉消息
- 创建研究任务
- 继续对话时创建 follow-up task
- 运行任务
- 拉取 workspace
- 查看 tools / skills

仍然待实现或处于过渡态：

- 历史页接口
- 更真实的上下文摘要压缩
- 自动决定是否立即运行 follow-up task
- 正式数据库持久化
- 完整 RAG / shared knowledge
- `auditor / synthesizer` 继续细拆

## 5. 开发建议

### 前端同学

优先围绕这些接口开发：

- `POST /conversations`
- `GET /conversations/{conversation_id}/messages`
- `POST /conversations/{conversation_id}/messages`
- `POST /conversations/continue`
- `POST /research/tasks/{task_id}/run`
- `GET /research/tasks/{task_id}/workspace`
- `GET /tools`
- `GET /skills`

### 后端同学

优先补这些实现：

- `continue_conversation` 的真实上下文逻辑
- workspace 中 `taxonomy / graph / trace` 的结构收紧
- tools / skills / knowledge 的扩展实现
- repository 的数据库版本

## 6. 结论

当前版本已经不只是“有接口骨架”，而是开始具备真正的产品主链路了：

**会话 -> 消息 -> follow-up task -> 运行任务 -> 工作台结果**

这条链路打通之后，组员会更容易知道自己是在补哪一段，而不是对着抽象占位函数发懵。
