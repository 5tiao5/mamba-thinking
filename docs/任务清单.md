## 2. 已完成能力

### 2.1 研究主链

- 创建、读取、删除会话。
- 写入和读取多轮消息。
- 创建并运行首轮研究任务。
- 追问自动形成 follow-up task。
- task 状态流转：`created -> running -> completed / failed`。
- 任务完成后回写 assistant 结果，并能打开对应工作台。

### 2.2 论文资产与检索

- 系统检索论文并形成扩展证据池。
- 相关性筛选后形成核心分析论文池。
- 记录本轮新增论文与沿用论文。
- 保留来源、日期、分类、引用数是否已知、相关性等级和相关性理由。
- 创建研究前或研究过程中批量导入 PDF。
- 通过标题、DOI、arXiv ID 或链接识别候选论文。
- 用户可选择导入到当前研究或共享知识。
- 研究方式支持 `hybrid / imported_only / search_only`。

### 2.3 结构化研究结果

- taxonomy 及分支论文映射。
- task 级研究关系图谱。
- graph edge 的关系类型、来源、置信度和证据片段。
- 研究空白和研究建议。
- 结论证据契约：
  - `supporting_paper_ids`
  - `evidence_level`
  - `evidence_reason`
- 前端可展开查看结论绑定的论文标题。

### 2.4 多轮研究沉淀

- task 级“本次结果”。
- conversation 级“本研究总览”。
- 总览聚合同一研究下已完成任务的论文、taxonomy、图谱、空白和建议。
- working memory 记录当前焦点、稳定发现、待解问题和活动约束。
- inherited context 记录历史 workspace 摘要、研究线索和近期追问。
- conversation workspace 已加入缓存和新任务完成后的失效机制。

### 2.5 RAG 与知识范围

- 知识文档新增、搜索、删除和 SQLite 持久化。
- 文档 chunk 检索、文档聚合和 supporting snippets。
- 低相关知识过滤和检索状态说明。
- `none / conversation_only / shared` 三种知识范围。
- 知识命中会进入研究上下文，但不会自动被当成论文证据。

### 2.6 Tool 与 Skill

- Tool 列表和启停。
- Skill 新增、编辑、启停和删除。
- Skill 依赖工具存在性与启用状态校验。
- 任务和追问支持 `selected_skill_ids`。
- 选中 Skill 的描述会进入研究上下文，并记录到任务 trace。

## 3. 当前最高优先级

### P0：检索结果稳定性

目标：同时做到“查得到”和“查得准”。

需要继续验证：

- 初次研究能否稳定召回足够的候选论文。
- 年份、方法、场景等追问是否真正触发补搜。
- query decomposition 是否覆盖用户全部约束。
- 主题擦边论文是否在进入核心分析池前被过滤。
- 不应使用无意义 seed 论文伪装成功。

验收方式：

- 固定 5 至 10 个研究主题。
- 每个主题包含首轮和至少两种追问。
- 记录候选数、核心数、新增数、跑题数和无结果原因。

固定主链用例见 [主链质量验收说明](主链质量验收说明.md)，结构化用例位于 `evaluation/main_chain_cases.json`。

### P0：结论可信度

目标：页面展示的结论能说明“依据什么得到”。

需要继续验证：

- taxonomy 分支的匹配论文是否真实显示。
- graph 强关系是否有引用或正文片段支撑。
- gaps / ideas 的绑定论文必须来自当前分析池。
- 无论文绑定的结论必须保持 `exploratory`。
- 研究总览合并后不能丢失论文元数据或证据等级。

### P1：研究总览语义合并

当前总览已能聚合多轮结果，并对近期追问赋予更高权重，但仍需检查：

- 早期高价值论文是否被最新一轮完全挤掉。
- 相互冲突的结论是否被识别，而不是简单拼接。
- working memory 是否真实反映多轮研究演化。
- 总览摘要是否准确描述新增、沿用和当前研究焦点。

### P1：RAG 产品解释

- 允许打开命中文档或查看更完整内容。
- 更直观地区分“进入上下文”和“支撑结论”。
- 继续过滤与研究主题无关的共享知识。
- 用专门 bad case 评估共享知识开启前后的变化。

### P1：演示稳定性

- 固定一条首轮研究和两条追问。
- 准备 PDF 导入、纯检索、混合研究三种演示口径。
- 明确弱证据图谱和探索性建议的解释话术。
- 保证引用数未知时显示“未获取”，不显示伪造的 `0`。

## 5. 建议分工

### 前端

1. 做 RAG 命中来源全文或详情入口。
2. 优化研究总览的信息层级与多轮演化表达。
3. 为检索失败、证据不足和探索性结论提供一致状态展示。
4. 维护 PDF、Skill、论文来源和证据展开交互。

### 后端

1. 维护通用 query decomposition 和覆盖检查。
2. 优化多源召回、相关性排序、年份约束和补搜策略。
3. 提高论文元数据继承与总览字段级合并稳定性。
4. 增加 graph 强关系的全文证据判定。
5. 建立可重复运行的检索与结论回归集。

### 组长

1. 冻结 API 字段语义，避免前后端各自猜测。
2. 用固定主链验收，而不是只看单元测试。
3. 记录 bad case、修复原因和优化前后数据。
4. 控制范围，优先保证答辩中最能体现价值的链路。

## 6. 答辩前最低验收线

1. 用户可新建研究并选择论文来源、知识范围和 Skill。
2. 用户可批量导入 PDF，也可让系统检索论文。
3. 首轮结果能展示核心论文、taxonomy、图谱、空白和建议。
4. 追问约束能影响检索，并在“本次结果”中看到新增论文。
5. “本研究总览”能体现多轮论文与结论融合。
6. graph 不把普通主题相似伪装成改进或引用关系。
7. gaps / ideas 能说明证据等级和绑定论文。
8. 知识命中与论文证据在产品语义上明确区分。

## 7. 一句话结论

**下一阶段不再以增加功能数量为目标，而以“论文有用、结论可信、多轮研究能沉淀”为验收标准。**
