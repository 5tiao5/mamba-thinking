# 任务清单

这份文档只做一件事：

**把当前哪些能力已经真的能用、哪些文件和函数还需要继续实现，写清楚。**

## 1. 当前已经完成的基线

当前仓库已经具备：

- `research_agent/`
  - 已完成 controller、runtime、pipeline、主要节点拆分
- `api/`
  - 已冻结第一版 FastAPI 接口骨架
- `services/`
  - 已有 conversation / message / research / workspace / tool / skill / knowledge 服务骨架
- `repositories/`
  - 已有 repository 接口和内存实现
- `ui/`
  - 已有 React + Vite + TypeScript + Router 骨架
- `docs/`
  - 已有架构、接口、分工、调用链、字段字典、时序图文档

所以现在不是从零开始，而是在已经冻结的骨架上继续填实现。

## 2. 当前真正可用的功能

这些功能不是占位，而是真的能跑通。

### 2.1 会话链路

- 创建会话
- 读取单个会话详情
- 拉取会话列表

相关文件：

- `product_agent/services/conversation_service.py`

说明：

- 当前已经补出会话列表与会话详情接口，但历史页前端页面还没真正接上
- 对外的“会话详情 / 会话列表 / 历史会话”接口还没有正式补出来
- 因此前端当前不要假设“读取会话”已经能直接联调

### 2.2 消息链路

- 创建消息
- 读取消息列表
- 获取最近上下文预览

相关文件：

- `product_agent/services/message_service.py`
- `product_agent/schemas/message.py`

### 2.3 继续对话 -> follow-up task

- 继续对话时会写入消息
- 可选创建一条 follow-up 研究任务记录

相关文件：

- `product_agent/api/handlers.py`
- `product_agent/services/research_service.py`

### 2.4 研究任务链路

- 创建研究任务
- 运行研究任务
- 状态流转：`created -> running -> completed / failed`

相关文件：

- `product_agent/services/research_service.py`

### 2.5 工作台链路

- 拉取 workspace 快照
- 返回 papers / gaps / ideas / trace 的最小结果结构

相关文件：

- `product_agent/services/workspace_service.py`
- `product_agent/services/workspace_mapper.py`

### 2.6 Tool / Skill

- 查看 tools 列表
- 更新 tool 启用状态（当前是内存态）
- 查看 skills 列表

## 4. 现在最适合组员做的工作

### 前端组最适合现在做的

1. 对话页消息流
2. follow-up task 交互
3. 工作台结果展示
4. 设置页 tools / skills 展示

为什么适合：

- 接口已经存在
- 返回字段已经比较稳定
- 能直接联调，不是纯占位页面

### 后端组最适合现在做的

1. `continue_conversation` 的真实上下文增强
2. workspace 结构继续收紧
3. 历史查询接口
4. tool / skill / knowledge 扩展
5. `auditor / synthesizer` 继续细拆

为什么适合：

- 主链路已经有了
- 现在是“把骨架变实”的阶段
- 不是完全抽象设计了

---

## 5. 组长现在最该盯的点

1. 接口字段不能漂移
2. handler 不要直接访问 repository
3. 前端不要直接理解旧版 Agent state
4. 新功能优先继续收敛到 `product_agent/`
5. 先做能联调的真链路，再做边角功能

---

## 6. 下一步建议顺序

### 第一优先级

打通对话页：

- 创建会话
- 发消息
- 继续追问
- 看见 follow-up task

### 第二优先级

打通工作台页：

- 运行任务
- 拉 workspace
- 展示 papers / gaps / ideas

### 第三优先级

- 接历史页
- 接 shared knowledge / RAG
- 继续把 workspace 字段结构化
