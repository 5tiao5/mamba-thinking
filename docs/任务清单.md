## 3. 当前仍待实现或待优化的内容

下面这些不是“完全没有”，而是“现在做得还不够，值得作为下一阶段重点”。

### 3.1 多轮会话体验还不够自然

现状：

- assistant 消息已经会回写
- 但内容更像“任务执行结果摘要”
- 还不够像真正连续对话式的研究助手

重点优化方向：

- 让 assistant 回复更像回答，而不是任务日志
- 更清楚地展示“这条消息触发了哪个 task”
- 让对话页与 workspace、历史页之间的跳转更自然

### 3.2 taxonomy 仍需继续收口

现状：

- taxonomy grounding 已经进入第二轮收口
- 宽问题 query decomposition 第一版已经接入
- taxonomy 节点已经开始 evidence-first

但仍存在的问题：

- 宽问题下真实证据仍然可能不足
- taxonomy 仍可能偏理想化
- 证据不足时更适合显示 `candidate branches`，而不是装成完整研究地图

下一步重点：

- 继续提升 evidence-aware 程度
- 把“证据不足模式”打磨成明确的产品逻辑

### 3.3 搜索质量仍值得继续优化

现状：

- searcher 能跑
- 宽问题 decomposition 第一版已接入
- fallback 仍会出现

问题：

- 有些问题仍会搜到“沾边但不够准”的论文
- 宽问题下真实论文数量可能太少
- fallback 触发后，结果虽然能跑完，但研究价值有限

下一步重点：

- 提高检索召回与筛选质量
- 继续降低 fallback 触发概率

### 3.4 knowledge / retrieval 还没真正接进主链

现状：

- 有 knowledge 导入 API
- 有 `KnowledgeService` 骨架
- 有 SQLite 持久化

但现在还没有真正做到：

- 用户导入知识后，后续 task 自动利用这些知识
- 会话追问前先做 retrieval

下一步重点：

- 在 `continue_conversation` 或 `run_task` 前接 retrieval
- 用导入知识降低 fallback

### 3.5 workspace 仍需继续产品化

现状：

- taxonomy map、graph、papers、insights 已经图形化
- conversation 页也已经开始把 task 打开入口做得更自然

但仍值得优化：

- taxonomy 的 evidence 解释更细
- graph 的交互能力更强
- fallback 结果提示更自然
- evidence-insufficient 模式下的页面更像“研究建议面板”

### 3.6 conversation 级总 workspace 还只是第一版

现状：

- 已经能聚合同一 conversation 下所有成功 task 的结果

但它目前仍然是：

- 读时聚合
- 没有单独 materialize
- 还没有显式区分“conversation 总结”和“某次 task 快照”

下一步重点：

- 是否要引入真正的 `ConversationWorkspace`
- knowledge 导入如何影响 conversation 总 workspace

### 3.7 CI/CD 与部署仍可后置

现状：

- 本地测试和前端构建都能过
- GitLab 私服 + GitHub mirror + Vercel/Render 的方案已经想清楚

但当前更重要的是：

- 先把产品逻辑与核心能力做稳
