# 本地环境变量说明

这份文档只讲一件事：

**组员本地要把 `.env` 放哪里、写什么、怎么启动。**

## 1. `.env` 放哪里

正确位置是：

- [product_agent/.env](/D:/iteration_two-master/iteration_two-master/product_agent/.env)

不要放在外层大目录。  
现在后端自动读取的是 `product_agent/.env`，不是外层 `.env`。

## 2. 怎么创建

在 `product_agent/` 根目录执行：

```powershell
cd D:\iteration_two-master\iteration_two-master\product_agent
Copy-Item .env.example .env
```

仓库里已经提供了示例文件：

- [.env.example](/D:/iteration_two-master/iteration_two-master/product_agent/.env.example)

## 3. 最少要填什么

常见情况至少填一项：

```env
OPENAI_API_KEY=your-key-here
```

如果你们后面也要切 DeepSeek，可以再加：

```env
DEEPSEEK_API_KEY=your-key-here
```

## 4. 加载规则

当前加载规则是：

1. 进程环境变量优先
2. `.env` 只补缺失值

所以：

- 如果你的系统环境变量里已经有 `OPENAI_API_KEY`，它不会被 `.env` 覆盖
- 如果组员本地没有配系统环境变量，直接在 `product_agent/.env` 里写也能跑

## 5. 启动方式

准备好 `.env` 后，直接在仓库根目录启动后端：

```powershell
cd D:\iteration_two-master\iteration_two-master\product_agent
python .\start_backend.py
```

前端：

```powershell
cd D:\iteration_two-master\iteration_two-master\product_agent\ui
npm install
npm run dev
```

## 6. 不要提交 `.env`

`.env` 只应该存在于本地，不应该提交进仓库。  
当前 [product_agent/.gitignore](/D:/iteration_two-master/iteration_two-master/product_agent/.gitignore) 已经忽略了 `.env`。

## 7. 常见误区

### 误区 1：把 `.env` 放到外层目录

现在不会默认读取外层目录的 `.env`，所以这样通常会导致：

- 后端能启动
- 但真正调用模型时提示缺少 API key

### 误区 2：只复制 `.env.example`，但没填 key

这时后端也许能起来，但一跑研究任务就会失败。

### 误区 3：组员以为必须手动在终端里 `set` 环境变量

现在不需要。  
只要 `product_agent/.env` 配好，`python .\start_backend.py` 就会自动加载。
