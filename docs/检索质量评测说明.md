# 检索质量评测说明

## 目标

这套评测用于回答两个产品问题：

1. **查得到**：用户提出合理科研主题后，系统能否返回足够的真实论文，而不是保底论文。
2. **查得准**：返回论文是否同时覆盖用户问题中的多个独立概念，而不是只命中一个宽泛词。

评测不是单纯检查搜索 API 是否返回数据，也不直接拿系统自己的 `relevance_score` 当正确答案。每个案例都包含一份人工编写的“主题契约”，独立描述概念组、年份范围、最低论文数量和明显跑题方向。

如果要验证“新建研究 -> 追问 -> 工作台 -> 研究总览”的完整产品链路，请同时参考 [主链质量验收说明](主链质量验收说明.md)。检索质量评测是底层能力检查，主链验收是产品体验和证据可信度检查。

## 数据集

数据位于：

`evaluation/retrieval_cases.json`

首版包含 10 个案例，覆盖：

- AI Agent 工具使用可靠性评测
- function calling 鲁棒性
- 软件工程 Agent
- Agent-Centric 软件开发方法论
- 软件工程 Agent 的 episodic memory
- 近两年与近三年的代码 Agent 论文
- 中英混输的多 Agent 软件工程工作流
- 科研助手 RAG 与证据引用
- LLM Agent failure modes

`landmark_titles` 只作为软检查。论文库会持续更新，未命中 landmark 不会单独判失败；真正的硬指标是概念覆盖、真实论文数量、直接证据数量和年份约束。

## 指标

- `real_paper_count`：排除 seed/fallback 后的真实论文数。
- `direct_paper_count`：系统判定为直接证据的论文数。
- `adjacent_paper_count`：仅覆盖部分概念、可用于补充背景的论文数。
- `precision_at_k`：结果中满足人工主题契约的论文比例。
- `constraint_pass_rate`：年份等硬约束的满足比例。
- `score`：查得到 35 分、查得准 35 分、直接证据 20 分、约束遵守 10 分。

## 使用方式

先只校验数据集结构：

```powershell
cd D:\product_agent
python .\evaluation\retrieval_quality.py --validate-only
```

运行一个快速案例：

```powershell
python .\evaluation\retrieval_quality.py --case agent_tool_use_evaluation
```

运行全部案例：

```powershell
python .\evaluation\retrieval_quality.py
```

报告默认写入 `outputs/retrieval_eval/`，包含 JSON 明细和 Markdown 汇总。网络 API 偶发超时时，不应立即修改相关性阈值；先区分是“数据源不可用”还是“返回结果跑题”。

## 团队回归规则

修改以下内容后，至少运行三个核心案例：

- query decomposition 或 retrieval plan
- arXiv / Semantic Scholar 查询构造
- relevance 分层阈值
- 年份过滤、补搜或论文补齐策略

建议固定运行：

```powershell
python .\evaluation\retrieval_quality.py `
  --case agent_tool_use_evaluation `
  --case software_engineering_agents `
  --case recent_two_years_code_agents
```

如果平均分提高但某个核心案例明显下降，应视为回归，而不是用平均分掩盖。
