# 需求分析文档

更新时间：2026-06-18

## 1. 项目背景

Product Agent 是一个面向科研调研场景的 Agent 应用。项目目标不是做一个通用聊天机器人，而是围绕“研究主题 -> 论文证据 -> 结构化分析 -> 多轮追问 -> 研究沉淀”形成完整闭环，帮助用户更快完成文献调研、方向梳理和选题判断。

课程迭代三要求强调 Agent 产品化：需要完整应用、可用界面、合理交互、文档记录和优化过程。基于这些要求，本项目把核心产品价值定义为：

**证据驱动的科研调研与选题决策助手。**

## 2. 用户与场景

| 用户 | 典型场景 | 主要痛点 |
| --- | --- | --- |
| 初入某个方向的学生 | 输入一个模糊研究主题 | 不知道该搜什么、先读哪些论文、领域主线是什么 |
| 已有本地论文的研究者 | 批量导入 PDF 后继续调研 | 不想手工整理论文贡献，也不想让系统忽略自己的论文 |
| 准备开题或组会的人 | 需要研究空白和建议 | 担心 AI 给出的建议没有论文支撑 |
| 多轮探索同一主题的用户 | 不断追问、收窄、扩展方向 | 普通对话容易忘记历史，结果难以沉淀 |
| 答辩或演示场景 | 需要解释系统如何工作 | 不能只展示一段文本，需要能追踪论文、结论和 Agent 过程 |

## 3. 核心需求

### 3.1 会话与多轮研究

- 用户可以新建研究会话，输入研究主题和会话标题。
- 用户可以在同一研究下多轮追问。
- 每次首轮生成或追问都可以形成独立研究任务。
- 系统需要区分“本次结果”和“本研究总览”：
  - 本次结果：聚焦一次生成或一次追问的局部结果。
  - 本研究总览：聚合同一研究主题下多轮任务的累积结果。

### 3.2 论文获取与证据池

- 支持系统从外部论文源检索论文。
- 支持用户在创建研究前或研究过程中导入 PDF。
- 支持通过标题、DOI、arXiv ID 或 arXiv 链接识别论文候选。
- 支持三种研究方式：
  - `hybrid`：导入论文 + 系统补搜。
  - `imported_only`：仅分析导入论文。
  - `search_only`：完全由系统检索。
- 系统必须保留论文来源身份，例如用户上传、系统检索、Semantic Scholar、arXiv。

### 3.3 结构化研究结果

- 生成核心论文与扩展证据池。
- 生成研究方向 taxonomy。
- 生成论文关系图谱。
- 生成研究空白和研究建议。
- 每条空白和建议都需要尽量绑定论文证据，并标注证据等级。
- 论文详情需要解释：
  - 这篇论文做了什么。
  - 为什么建议先读。
  - 能支撑当前研究的什么问题。
  - 哪些结论还不能直接相信。

### 3.4 知识与上下文

- 支持共享知识库。
- 支持当前研究私有知识。
- 支持关闭知识增强。
- 知识命中只能作为上下文参考，不能自动冒充当前论文证据。
- 系统需要沉淀 working memory，包括当前焦点、稳定发现、待解问题和活动约束。

### 3.5 Agent 可观察性

- 用户在等待系统生成时，应能看到 Agent 正在做什么。
- Agent 运行过程需要展示关键节点，例如 Planner、Searcher、Taxonomy、Evolution、Auditor、Corrector、Synth、Result。
- 运行结束后，等待画板应在结果刷新完成后自动收起，不能让用户误以为任务卡住。

### 3.6 Tool 与 Skill

- 用户可以查看和启停工具。
- 用户可以新增、编辑、启停、删除 Skill。
- Skill 可以绑定需要的工具，并在任务中被选择。
- 当前 Skill 更接近“研究策略模板/能力描述”，不等价于完整插件市场或可执行外部代码。

## 4. 非功能需求

| 类型 | 要求 |
| --- | --- |
| 可用性 | 主链可以从新建研究跑到追问与工作台展示 |
| 可解释性 | 论文、图谱、空白、建议都要有来源或证据边界 |
| 稳定性 | 检索失败不能静默用 seed 论文伪装成功 |
| 可维护性 | 前端依赖 API 合同，后端 handler 不直接访问 repository |
| 可扩展性 | 保留多源检索、PDF 分析、LLM 简报、并行分析的扩展点 |
| 可评测性 | 固化检索质量评测集和主链验收用例 |

## 5. 当前完成度

当前项目已经完成课程要求中的主要功能闭环：

- 完整 Web Agent 应用。
- 会话、追问、任务、工作台、历史记录。
- 系统检索、PDF 导入、论文候选导入。
- 共享知识、当前研究知识、RAG 命中和 working memory。
- Tool 与 Skill 的基础管理。
- taxonomy、论文关系图谱、研究空白、研究建议。
- Agent 运行图和任务事件记录。

当前仍需持续优化的重点是结果质量，而不是继续横向堆功能：

- 检索召回与相关性。
- 多轮总览合并。
- 图谱强关系的证据质量。
- 论文详情和全文 claim verification。
- 固定主链质量验收。

## 6. 验收标准

最低验收线见 [任务清单](任务清单.md) 和 [主链质量验收说明](主链质量验收说明.md)。核心标准如下：

1. 用户可以新建研究并选择论文来源、知识范围和 Skill。
2. 用户可以批量导入 PDF 或让系统检索论文。
3. 首轮结果能展示核心论文、taxonomy、关系图谱、空白和建议。
4. 追问约束能影响检索，并能看到新增或沿用论文。
5. 本研究总览能融合多轮结果，而不是只覆盖成最新一轮。
6. 引用数未知不能显示为确定的 `0`。
7. RAG 命中不能直接伪装成论文证据。
8. 空白和建议必须说明证据等级和绑定论文。
