# 字段字典

本文档用于统一当前 `product_agent/` 的核心数据对象含义。

适用场景：

- 前端同学不知道某个字段是干嘛的
- 后端同学不确定某个字段该在哪一层使用
- 组长 review 时想快速判断字段有没有漂移

- [架构设计说明](D:/iteration_two-master/iteration_two-master/product_agent/docs/架构设计说明.md)
- [接口与函数参考文档](D:/iteration_two-master/iteration_two-master/product_agent/docs/接口与函数参考文档.md)
- [调用关系参考](D:/iteration_two-master/iteration_two-master/product_agent/docs/调用关系参考.md)

## 1. Domain 层对象

这些对象定义在：

- `product_agent/domain/entities.py`

它们更偏“系统内部业务对象”，不一定和前端返回结构一模一样。

### 1.1 `Conversation`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `conversation_id` | `str` | 会话唯一标识 | 前后端共用主键 |
| `title` | `str` | 会话标题 | 可由用户给定，也可默认回退到 topic |
| `topic` | `str` | 会话围绕的研究主题 | 会话级主线 |
| `status` | `str` | 会话状态 | 当前默认 `active` |
| `message_ids` | `List[str]` | 消息 ID 列表 | 用于会话和消息关联 |
| `latest_task_id` | `Optional[str]` | 最近任务 ID | 方便历史页和工作台跳转 |
| `created_at` | `datetime` | 创建时间 | 后端内部使用 |
| `updated_at` | `datetime` | 更新时间 | 后端内部使用 |

### 1.2 `MessageRecord`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `message_id` | `str` | 消息唯一标识 | 消息层主键 |
| `conversation_id` | `str` | 所属会话 ID | 与 `Conversation` 关联 |
| `role` | `str` | 消息角色 | 例如 `user / assistant / system` |
| `content` | `str` | 消息正文 | 多轮对话核心内容 |
| `metadata` | `Dict[str, Any]` | 扩展元数据 | 可放 focus、引用、任务触发信息 |
| `created_at` | `datetime` | 创建时间 | 排序与历史展示使用 |

### 1.3 `ResearchTask`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `task_id` | `str` | 任务唯一标识 | 分析任务主键 |
| `conversation_id` | `str` | 所属会话 ID | 一个会话下可有多个任务 |
| `topic` | `str` | 本次任务分析主题 | 可与会话 topic 相同或更细 |
| `status` | `str` | 任务状态 | 当前约定 `created / running / completed / failed` |
| `trigger_message_id` | `Optional[str]` | 触发该任务的消息 ID | follow-up task 很依赖这个字段 |
| `mode` | `str` | 运行模式 | 当前约定 `default / fast / balanced` |
| `created_at` | `datetime` | 创建时间 | 用于历史记录 |
| `updated_at` | `datetime` | 更新时间 | 用于状态流转 |

### 1.4 `PaperRecord`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `paper_id` | `str` | 论文唯一标识 | 当前通常来自 arXiv id 等 |
| `title` | `str` | 论文标题 | 建议保留英文原文 |
| `abstract` | `str` | 摘要 | 当前主要来自检索源 |
| `authors` | `List[str]` | 作者列表 | 前端可选择简化展示 |
| `publish_date` | `str` | 发表日期 | 当前先用字符串 |
| `source` | `str` | 来源 | 如 `arxiv`、`semantic_scholar` |
| `taxonomy_category` | `str` | taxonomy 分类 | 工作台筛选会用到 |
| `citation_count` | `int` | 引用数 | 当前不一定总是稳定 |
| `url` | `str` | 外部链接 | 用于跳转到论文页面 |

### 1.5 `GapRecord`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `gap_id` | `str` | gap 唯一标识 | 当前由 mapper 生成 |
| `task_id` | `str` | 所属任务 ID | 与 workspace 关联 |
| `summary` | `str` | gap 概述 | 对用户最重要的字段 |
| `severity` | `str` | 严重程度 | 当前默认 `medium` |
| `evidence` | `List[str]` | 支撑证据 | 后续应该更结构化 |

### 1.6 `ResearchIdeaRecord`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `idea_id` | `str` | 研究建议唯一标识 | 当前由 mapper 生成 |
| `task_id` | `str` | 所属任务 ID | 与 workspace 关联 |
| `title` | `str` | 研究选题标题 | 最适合卡片展示 |
| `motivation` | `str` | 动机 | 为什么值得做 |
| `approach` | `str` | 方法思路 | 怎么做 |
| `feasibility` | `str` | 可行性 | 实现难度和资源要求 |
| `contribution` | `str` | 预期贡献 | 对研究方向的意义 |

### 1.7 `ResearchWorkspace`

这是产品层最重要的对象。

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `task_id` | `str` | 对应任务 ID | 工作台和任务一一对应 |
| `topic` | `str` | 当前分析主题 | 页面抬头展示 |
| `summary` | `str` | 工作台摘要 | 当前来自报告截断 |
| `papers` | `List[PaperRecord]` | 论文列表 | 工作台主体之一 |
| `taxonomy` | `Dict[str, Any]` | 分类结构 | 当前还偏松，后续要结构化 |
| `graph_edges` | `List[Dict[str, Any]]` | 图谱边 | 当前还偏松，后续要结构化 |
| `gaps` | `List[GapRecord]` | gap 列表 | 审计结果的重要部分 |
| `ideas` | `List[ResearchIdeaRecord]` | 研究建议 | 用户价值最高的结果之一 |
| `alignment_score` | `float` | 对齐分数 | 量化当前结果质量 |
| `trace` | `Dict[str, Any]` | 过程轨迹 | 当前包含 thought/action 等 |

### 1.8 `ToolDescriptor`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `tool_id` | `str` | 工具唯一标识 | 如 `arxiv_search` |
| `display_name` | `str` | 展示名 | 设置页显示 |
| `description` | `str` | 描述 | 给用户和开发者看 |
| `enabled` | `bool` | 是否启用 | 设置页控制项 |
| `config` | `Dict[str, Any]` | 工具配置 | 后续可持久化 |

### 1.9 `SkillDescriptor`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `skill_id` | `str` | skill 唯一标识 | 如 `paper_compare` |
| `display_name` | `str` | 展示名 | 设置页显示 |
| `description` | `str` | 描述 | 功能说明 |
| `enabled` | `bool` | 是否启用 | 后续可控制 |
| `prompts` | `Dict[str, str]` | prompt 配置 | 预留 |
| `required_tools` | `List[str]` | 依赖工具 | 用于校验 |

### 1.10 `KnowledgeDocument`

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `document_id` | `str` | 知识文档唯一标识 | RAG 主键 |
| `title` | `str` | 文档标题 | 可来自 report 或 summary |
| `source_task_id` | `Optional[str]` | 来源任务 ID | 方便追溯 |
| `content` | `str` | 文档正文 | 当前仍是整块文本 |
| `tags` | `List[str]` | 标签 | 后续做 topic/tag 检索 |
| `metadata` | `Dict[str, Any]` | 扩展元数据 | 可存时间、来源类型等 |

## 3. 哪些字段最容易漂移

当前最需要警惕的漂移点有：

- `ResearchWorkspace.taxonomy`
- `ResearchWorkspace.graph_edges`
- `ResearchWorkspace.trace`
- `WorkspaceSnapshotResponse.taxonomy`

原因很简单：

- 现在它们还是 `Dict[str, Any]` 或比较松的结构
- 前端一旦深度依赖具体字段，就容易和后端理解不一致

建议：

- 在前端正式深接 `taxonomy / graph / trace` 之前，再补一轮更细的 view model

---

## 4. 字段使用原则

### 原则 1

前端优先依赖 `schemas/`，不要直接依赖 `domain/`

### 原则 2

后端内部编排优先用 `domain/`，不要让 handler 直接拼原始字典

### 原则 3

旧版 Agent 的 `state` 只能通过 `workspace_mapper` 投影出来，不能直接暴露给前端

---

## 5. 一句话总结

如果组员看到一个字段，不确定它到底是不是给前端用的，可以先问自己：

- 它在 `domain/` 里，还是在 `schemas/` 里？

通常：

- `domain/` 更偏内部业务结构
- `schemas/` 更偏接口合同

前端真正应该信的是后者。
